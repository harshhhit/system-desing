Distributed Database Fundamentals

Lecture notes — databases & distributed systems. A companion to the Distributed Data Roadmap covering CAP, ACID, replication methods, consistency models, and CDC.

1. CAP Theorem

In a distributed database you can only guarantee two of three at any given time:

  • C — Consistency: every read gets the latest write, or an error.
  • A — Availability: every request gets a response, even if it's not the latest.
  • P — Partition tolerance: the system keeps operating despite network partitions.

Trade-offs:

  • CP system: prioritizes consistency + partition tolerance → sacrifices availability.
  • AP system: prioritizes availability + partition tolerance → sacrifices strict consistency.
  • CA system: possible only in a non-partitioned single-node system.

2. ACID Properties

  • Atomicity: a transaction is all-or-nothing.
  • Consistency: only valid data (meeting constraints) is stored.
  • Isolation: transactions don't affect each other during execution.
  • Durability: once committed, data is permanent.

Relational DBs typically provide full ACID. Non-relational DBs often relax isolation for performance and scalability.

3. Isolation in Non-Relational Databases

  • Many NoSQL DBs (MongoDB, Cassandra) provide weaker isolation such as read-committed or eventual consistency.
  • Isolation is often tuned via consistency levels:
    • Read Concern / Write Concern in MongoDB.
    • Quorum reads/writes in Cassandra.

4. Distributed Systems Concepts

  • Partitioning (sharding): splitting data across nodes for scalability.
  • Replication: copying data to multiple nodes for availability and durability.

5. Database Replication Methods

  • Synchronous: writes wait until all replicas confirm.
  • Asynchronous: writes return immediately; replicas update later.
  • Semi-synchronous: the leader waits for at least one replica to confirm.
  • Multi-master: multiple nodes can accept writes.
  • Log-based: replicas replay the leader's change logs.

6. Consistency Models

  • Strong (real-time): all nodes always return the latest value.
  • Near real-time: small replication delay (milliseconds–seconds).
  • Eventual: updates propagate eventually; reads may be stale.
  • Periodic: data syncs at fixed intervals.

7. Change Data Capture (CDC)

  • Captures changes in real time from DB logs or triggers.
  • Useful for replication, streaming, analytics, and sync with search engines.

8. Full Load

Initial bulk load of all data into a new system before incremental updates begin.

9. Search Optimization

  • Full-text search engines like OpenSearch and Elasticsearch index data for fast keyword queries.
  • Confidence score: indicates relevance of results.

10. Keys in Databases

  • Primary key: unique identifier for a row.
  • Foreign key: enforces a link between tables and referential integrity.

11. Load Balancers in Multi-AZ / Multi-Region

Load balancers (AWS ALB, GCP LB) can distribute traffic across:

  • Multiple Availability Zones — fault tolerance within a region.
  • Multiple regions — disaster recovery and global latency reduction.
