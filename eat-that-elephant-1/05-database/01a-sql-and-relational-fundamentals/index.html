SQL and Relational Fundamentals

Study prompt: Learn tables, rows, columns, primary and foreign keys, normalization, CRUD, filtering, joins, aggregation, subqueries, and constraints. Practice by modeling a small order-management database and writing queries for it.

Core Building Blocks

ConceptWhat it means
Table / row / columnA table is a typed collection of rows; each row is one record, each column one attribute.
Primary keyColumn(s) that uniquely identify a row. Should be stable and rarely, if ever, updated.
Foreign keyA column referencing another table's primary key, enforcing referential integrity.
Composite keyA primary or unique key made of more than one column (e.g. (order_id, product_id)).
ConstraintNOT NULL, UNIQUE, CHECK, and foreign keys — rules the database enforces on every write.

Normalization

FormRule
1NFEvery column holds a single, atomic value — no repeating groups or arrays crammed into one field.
2NF1NF, plus every non-key column depends on the whole primary key (matters once keys are composite).
3NF2NF, plus no non-key column depends on another non-key column (no transitive dependencies).
BCNFA stricter 3NF: every determinant must be a candidate key.

Normalize to remove update anomalies; denormalize deliberately (with a documented reason) when read performance requires it — see Schema Design and Migrations.

Joins

JoinReturns
INNER JOINOnly rows with a match on both sides.
LEFT JOINAll rows from the left table, matched columns or NULL from the right.
RIGHT JOINMirror of LEFT JOIN — all rows from the right table.
FULL OUTER JOINAll rows from both sides, NULL-padded where there's no match.
CROSS JOINCartesian product — every row from the left paired with every row from the right.

Aggregation and Subqueries

  • GROUP BY / HAVING: aggregate rows into groups, then filter groups (not raw rows) with HAVING.
  • Window functions: ROW_NUMBER(), RANK(), running totals — compute per-row values across a related set without collapsing rows.
  • Subqueries: uncorrelated subqueries run once; correlated subqueries re-run per outer row and can be slow at scale.
  • CTEs (WITH): name a subquery for readability and reuse within one statement.
Common pitfalls

SELECT * in production code, missing indexes on foreign key columns, comparing to NULL with = instead of IS NULL, and accidental cartesian joins from a missing or wrong ON clause.
