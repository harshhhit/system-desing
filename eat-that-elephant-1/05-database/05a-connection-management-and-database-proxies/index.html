Connection Management and Database Proxies

Study prompt: Learn connection pooling, pool sizing, timeouts, connection leaks, health checks, failover, and database proxies such as PgBouncer and ProxySQL. Understand when read/write routing is safe and how replication lag can return stale data.

Why Pooling Matters

Opening a database connection is expensive — TCP handshake, auth, TLS, session setup. Under real traffic, opening one per request exhausts the database's connection limit long before it exhausts CPU. A connection pool keeps a bounded set of live connections open and hands them out to requests as needed.

Sizing the Pool

  • More connections isn't always faster — each one costs the database memory and adds contention; an oversized pool can make throughput worse.
  • A common starting point is small (e.g. 2 × CPU cores per database instance) and tuned from measured saturation, not guessed.
  • Every service instance has its own pool — with many instances, total connections across all of them must stay under the database's hard limit.

Common Failure Modes

SymptomLikely cause
Requests hang waiting for a connectionPool exhausted — often a connection leak (a code path that never returns its connection) rather than genuine load.
"Too many connections" errors from the databaseSum of all pools across all service instances exceeds the database's max_connections.
Intermittent timeouts after failoverPooled connections still pointing at the old primary — needs a health check that evicts dead connections.

Database Proxies

Tools like PgBouncer (Postgres) and ProxySQL (MySQL) sit between the application and the database and multiplex many client connections onto far fewer real database connections — useful when many service instances would otherwise each hold their own large pool.

Read/write routing

Routing reads to a replica is only safe if the application can tolerate replication lag — a write followed immediately by a read of the same row can return stale data on a lagging replica. Route "read your own write" paths to the primary, or read from the replica only where slightly stale data is acceptable.
