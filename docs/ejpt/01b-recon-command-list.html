Network Reconnaissance Command List

Every recon command by purpose — addressing, routing, reachability, DNS, TCP ports, Nmap, listeners, path, packets and Docker — plus the 15-step execution sequence and a self-check.

What you'll learn

By the end of this page you will be able to:

  • Pick the right command for each recon question: addressing, routing, reachability, DNS, ports, services, path and packets
  • Run the full 15-step recon sequence in a sensible order
  • Say what the important flags on each command do
  • Explain the 15 core concepts behind these commands without notes

Pentesting Lab — Network Reconnaissance Command List

This is the consolidated list of commands covered in this lesson, organized by purpose and execution order.

It is the quick-reference companion to Network Reconnaissance During Penetration Testing, which explains the theory behind each command — what an IP address, a route, ICMP, DNS, a TCP handshake and ARP are. This page does not repeat those explanations; it gives you the commands grouped by the question they answer, then the order to run them in.

💡 Important

Replace TARGET_IP, TARGET, PORT and SUBNET with your authorized lab values. Every command here assumes a lab or an engagement you are permitted to test.

Complete Practical Execution Sequence

This is the recommended sequence whenever you start network reconnaissance in your authorized pentesting lab. It moves from what you can learn about your own machine (no traffic to the target), to light single-packet checks, to scanning — so each step explains the result of the next.

StepCommandObjective
1ip -br addrIdentify IP addresses
2ip routeIdentify gateway and routes
3ip route get TARGET_IPUnderstand traffic path
4ping -c 4 TARGET_IPTest ICMP connectivity
5ip neighCheck neighbour table
6netdiscover -r SUBNETDiscover local hosts
7getent hosts TARGETResolve hostname
8dig TARGETInvestigate DNS
9nc -vz TARGET_IP PORTTest TCP connectivity
10nmap -sn SUBNETDiscover responsive hosts
11nmap -sT TARGET_IPIdentify TCP port states
12nmap -sV TARGET_IPIdentify services and versions
13ss -tulnpCheck local listening services
14traceroute TARGET_IPInvestigate network path
15tcpdump -i anyAnalyze network packets

Replace TARGET_IP, TARGET, PORT and SUBNET with your authorized lab values.

The same sequence grouped into phases:

  1. Know yourself (steps 1–3): ip -br addr, ip route, ip route get TARGET_IP — which networks you are on and which way traffic to the target will leave. Nothing is sent to the target yet.
  2. Is it there? (steps 4–6): ping, ip neigh, netdiscover — ICMP reachability and Layer 2 neighbours on your own segment.
  3. What is it called? (steps 7–8): getent hosts resolves the name the way applications on your box do; dig asks DNS directly.
  4. What is open? (steps 9–12): nc -vz for one port, then nmap -sn, nmap -sT and nmap -sV for hosts, port states and service versions.
  5. Explain anything odd (steps 13–15): ss -tulnp for your own listeners, traceroute for where the path stops, tcpdump for what actually went over the wire.

🧠 Think about it

Why does step 3 (ip route get) come before step 4 (ping)? If the route sends traffic out the wrong interface — say, not through the VPN — a failed ping tells you nothing about the target.

Commands by Purpose

Ten groups, each answering one recon question. Each block is followed by what its important flags do.

1. IP Addressing & Network Interfaces

Understand your machine's IP addresses, interfaces and subnets.

ip addr
ip a
ip -br addr
ip -4 addr
ip -6 addr
  • ip a — short form of ip addr; same output.
  • ip -br addr — brief mode: one line per interface (name, state, addresses).
  • ip -4 addr / ip -6 addr — show only IPv4 or only IPv6 addresses.

Theory: IP addressing and CIDR.

2. Routing & Gateway

Understand how network traffic reaches its destination.

ip route
ip route show
ip route get 8.8.8.8
ip route get TARGET_IP
  • ip route show — the explicit form of ip route; prints the routing table.
  • ip route get TARGET_IP — which gateway, interface and source IP Linux would use for that one destination.

Theory: routing and the default gateway.

3. Host Discovery & Connectivity

Check whether other machines respond to network requests.

ping TARGET_IP
ping -c 4 TARGET_IP
ping -i 2 TARGET_IP
ping -W 2 -c 4 TARGET_IP
  • -c 4 — send four Echo Requests, then stop and print a summary.
  • -i 2 — wait two seconds between packets.
  • -W 2 — wait at most two seconds for each reply.

Check local network neighbours:

ip neigh

Discover devices using ARP:

netdiscover -r 192.168.1.0/24
  • ip neigh — the cached IP-to-MAC (ARP) table: hosts your machine has recently talked to on its segment.
  • netdiscover -r — actively ARP-scan the given range; only works within your own Layer 2 segment.

Theory: ICMP and ping, ARP and Netdiscover.

4. DNS Resolution & Investigation

Understand how hostnames resolve to IP addresses.

getent hosts google.com
getent hosts TARGET

Inspect DNS configuration:

cat /etc/hosts
cat /etc/resolv.conf
cat /etc/nsswitch.conf

DNS queries:

dig google.com
dig A google.com
dig AAAA google.com
  • /etc/hosts — static name-to-IP mappings, checked before DNS when NSS says hosts: files dns.
  • /etc/resolv.conf — which DNS servers this machine queries.
  • /etc/nsswitch.conf — the order of name sources (files, DNS, …) that getent follows.
  • dig A / dig AAAA — ask DNS only for IPv4 or IPv6 records; dig ignores /etc/hosts.

Theory: DNS and getent vs. nslookup.

5. TCP Port Connectivity

Check whether specific TCP ports are accessible.

nc -vz TARGET_IP 22
nc -vz TARGET_IP 80
nc -vz TARGET_IP 443
nc -vz TARGET_IP 3306
nc -vz TARGET_IP 5432
nc -vz TARGET_IP 6379

Check multiple ports:

nc -vz TARGET_IP 22 80 443 3306 5432

Set connection timeout:

nc -vz -w 3 TARGET_IP 443
  • -v — verbose: print succeeded / refused / timed out.
  • -z — zero-I/O: complete the handshake, send no application data.
  • -w 3 — give up after three seconds, so a filtered port doesn't hang.
  • Ports: 22 SSH, 80 HTTP, 443 HTTPS, 3306 MySQL, 5432 PostgreSQL, 6379 Redis.

Theory: TCP, Netcat and the three result types.

6. Nmap — Host & Port Scanning

Discover open ports and identify services.

nmap TARGET_IP

TCP connect scan:

nmap -sT TARGET_IP

Scan specific ports:

nmap -p 22,80,443,5432 TARGET_IP

Service and version detection:

nmap -sV TARGET_IP

Host discovery:

nmap -sn 192.168.1.0/24
  • nmap TARGET_IP — scans the 1,000 most common TCP ports; as root it uses a SYN scan, as a normal user a connect scan.
  • -sT — TCP connect scan: completes the full three-way handshake on each port, like nc -vz at scale; needs no root.
  • -p 22,80,443,5432 — scan only these ports.
  • -sV — probe open ports to identify the service and its version.
  • -sn — host discovery only (which hosts respond), no port scan.

⚠️ Common mistake

Netdiscover vs. Nmap — the difference is reach. Netdiscover only sends ARP, so it sees hosts on your own Layer 2 segment and nothing beyond a router or Docker bridge. Nmap works across routed networks and also scans ports and services. An empty Netdiscover result on a different segment proves nothing.

7. Local Listening Ports & Services

Identify services listening on your own machine.

ss -tulnp
  • -t TCP · -u UDP · -l listening sockets only · -n numeric addresses and ports · -p owning process.

8. Network Path Analysis

Understand the path packets take to reach a destination.

traceroute 8.8.8.8

Alternative:

tracepath 8.8.8.8
  • Both list the routers (hops) between you and the destination, so you can see where responses stop.
  • tracepath needs no root and also reports the path MTU.

9. Packet Capture & Traffic Analysis

Observe actual network communication.

Capture all traffic:

tcpdump -i any

Capture ICMP:

tcpdump -i any icmp

Capture HTTPS traffic:

tcpdump -i any port 443

Capture traffic from a specific host:

tcpdump -i any host TARGET_IP

Stop capture:

Ctrl + C
  • -i any — capture on every interface.
  • icmp, port 443, host TARGET_IP — capture filters: only matching packets are shown.

🔥 Production insight

When a scan result looks wrong, run tcpdump -i any host TARGET_IP in a second terminal while you repeat it. Outgoing SYNs with no reply point at a drop on the path; no SYNs leaving at all point at your own routing.

10. Docker Network Investigation

Understand container networking and network isolation.

List Docker networks:

docker network ls

Inspect Docker bridge:

docker network inspect bridge

List running containers:

docker ps

Inspect a container:

docker inspect CONTAINER_NAME

Check networking inside a container:

docker exec -it CONTAINER_NAME ip addr
docker exec -it CONTAINER_NAME ip route
  • docker network inspect bridge — the bridge's subnet, gateway and which containers are attached with which IPs.
  • docker exec … ip addr / ip route — the container's own network namespace, which differs from the host's.

Theory: why ARP discovery stops at Docker bridges.

Best Practices

Do

  • Follow the sequence order — cheap, local checks first, so a scan result is never misread because of a routing or DNS problem.
  • Always set timeouts (nc -w, ping -W) — filtered ports and silent hosts otherwise stall the workflow.
  • Compare getent hosts with dig — a difference means /etc/hosts is overriding DNS.

Avoid

  • Using placeholder values outside your lab — every TARGET_IP / SUBNET must be in your authorized scope.
  • Treating a failed ping or an empty Netdiscover as "no host" — confirm with a TCP check or nmap -sn.

Interview Answer — What Is the Network Reconnaissance Command Workflow?

The network reconnaissance command workflow is the ordered set of Linux tools a tester runs to map a network before assessing it. It starts on the tester's own machine — ip addr for interfaces and subnets, ip route and ip route get for the path traffic will take — because every later result depends on knowing which network you are on and how packets leave.

It then moves outward in increasing cost and visibility: ping and ip neigh / netdiscover for reachability and Layer 2 neighbours, getent hosts and dig for name resolution, nc -vz for single-port TCP checks, and Nmap for host discovery (-sn), port states (-sT) and service versions (-sV). Finally ss, traceroute and tcpdump explain anything that doesn't add up. See the 15-step sequence.

Simple interview version

"I go from local to remote, cheapest first: ip addr and ip route to know my networks and path, ping and ARP for reachability, getent and dig for DNS, nc for a single port, then Nmap for hosts, ports and service versions. If results look wrong, I check ss, traceroute and tcpdump to see what actually happened on the wire."

One important interview follow-up

Q: Why not just start with nmap?

A: Because Nmap's output only makes sense once you know your own addressing and routing. If traffic is leaving the wrong interface, if DNS resolves the name to a stale IP, or if the target is on a different Layer 2 segment, Nmap will report hosts as down or ports as filtered and you will misread a local problem as a property of the target. The local checks take seconds and make every scan result interpretable.

Practice questions

What is an IP address?

A logical address assigned to a network interface that identifies where that interface sits in an IP network. One machine can have several (for example eth0, docker0, tun0), one per interface.

What is CIDR and subnetting?

CIDR notation (/24) says how many leading bits of an address are the network portion; the rest are host bits. A /24 has 8 host bits: 256 addresses, 254 traditionally usable. Subnetting is splitting a network into smaller ranges by using a longer prefix.

What is a default gateway?

The next hop that receives traffic for any destination not matched by a more specific route — usually the local router. In ip route it is the default via … line.

What is routing?

The decision of which interface and next-hop gateway a packet uses to reach its destination, made from the routing table. Same-subnet destinations go out directly; others go to a gateway.

What is ARP?

Address Resolution Protocol: on an IPv4 local network it finds the MAC address for an IP address by broadcasting "Who has X?" and receiving "X is at MAC". It works only inside one Layer 2 segment.

What is ICMP?

Internet Control Message Protocol: a network-layer protocol for errors and diagnostics, with no port numbers. ping sends ICMP Echo Requests and waits for Echo Replies.

What is DNS resolution?

Translating a hostname into an IP address. On Linux the order of sources comes from NSS (/etc/nsswitch.conf), typically /etc/hosts first, then the DNS servers listed in /etc/resolv.conf.

What is the TCP three-way handshake?

How TCP opens a connection: the client sends SYN, the server answers SYN-ACK, the client replies ACK. A successful nc -vz or nmap -sT result means this handshake completed.

What is the difference between TCP and UDP?

TCP is connection-oriented: a handshake first, then reliable, ordered delivery. UDP is connectionless: no handshake and no delivery guarantee. That is why UDP ports are harder to scan — silence can mean open or filtered.

What is a port?

A number (0–65535) that identifies a service endpoint on a host. The IP picks the machine; the port picks the service on it — e.g. 22 for SSH, 443 for HTTPS, 5432 for PostgreSQL.

What is the difference between open, closed and filtered ports?

Open: an application accepts connections (the handshake completes). Closed: the host is reachable but answers with a rejection — nothing is listening. Filtered: no usable answer, usually because a firewall drops the probes, so the scanner cannot tell open from closed.

What is the difference between Netdiscover and Nmap?

Netdiscover only uses ARP, so it finds hosts (IP and MAC) on your own Layer 2 segment. Nmap works across routed networks, discovers hosts with several probe types and also scans ports, services and versions.

Ping to a lab host shows 100% packet loss, but you suspect SSH is running. Why can ping fail even when a service is accessible?

The host, a firewall, a network ACL or a security group can block ICMP while still allowing TCP to port 22. Confirm with nc -vz -w 3 TARGET_IP 22 instead of concluding the host is down.

Why does Docker networking affect host discovery?

Each container has its own network namespace, and each Docker bridge is its own Layer 2 segment. ARP broadcasts don't cross bridges or routers, so ARP tools like Netdiscover can't see containers on another bridge — use IP-based discovery and check the networks with docker network inspect.

nc to a port keeps timing out. How does tcpdump help troubleshoot network communication?

It shows the packets that actually go over the wire instead of a tool's summary. With tcpdump -i any host TARGET_IP running, retry the check: SYNs leaving with no reply means something on the path drops them; a reset coming back means the port is closed; no SYNs at all means your own routing sends them elsewhere.

What Should I Remember?

  1. Ten command groups, one recon question each: addressing, routing, reachability, DNS, TCP ports, Nmap, local listeners, path, packets, Docker.
  2. Run them local-first and cheapest-first — the 15-step sequence.
  3. ip route get TARGET_IP before anything that sends traffic.
  4. getent follows NSS (/etc/hosts then DNS); dig asks DNS only.
  5. nmap -sn finds hosts, -sT finds port states, -sV finds service versions.
  6. Netdiscover stops at your Layer 2 segment; Nmap doesn't.
  7. tcpdump settles any disagreement between tools.

Quick commands

  • ip -br addr — interfaces and addresses
  • ip route get TARGET_IP — path to one destination
  • ping -W 2 -c 4 TARGET_IP — ICMP check with a timeout
  • getent hosts TARGET — resolve like an application
  • nc -vz -w 3 TARGET_IP PORT — one TCP port
  • nmap -sn SUBNET — responsive hosts
  • nmap -sV TARGET_IP — services and versions
  • ss -tulnp — local listeners
  • tcpdump -i any host TARGET_IP — what is on the wire
